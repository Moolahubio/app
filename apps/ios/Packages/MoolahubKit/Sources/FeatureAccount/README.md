## Keep (AppFeature calls this)

## What is here (v2)
1. **Account** (B5.1 amended) `AccountRootView.swift`: identity block (64 pt `AvatarView`, name, @username, email; `account.header`), then one flat list of `SettingsRow`s on the page (symbols at x 16, titles at x 52), groups split by `SettingsGroupDivider`: Profile, Security, Notifications, **Streak frequency** (`flame`, pushes `AppDestination.streakFrequency`; its value is `StreakWords.frequencyName` of `services.streaks.overview` when the shared store already holds one, else none; never loads it); **Learn** (`book.closed`, pushes `AppDestination.learn`), Technical details, About and legal; the Debug-only "Developer settings" row (`services.navigator.present(.developerSettings)`, inside `#if DEBUG`); **Deactivate account** (`pause.circle`, no chevron via `SettingsRow(showsChevron: false)`, its B5.14 dialog attached to the row, then `AccountStepUpSheet`) and **Delete account** (`trash`, a navigation row to `AccountRoute.deleteAccount`); the destructive "Sign out" row with its confirmation dialog (B5.2, attached to the row). Pull to refresh calls `services.session.refreshUser()` and shows an `ErrorBanner` when it fails.
   - **Confirm it's you** (B5.15) `AccountStepUpSheet.swift`: one sheet for both actions (`AccountSheet.stepUp(AccountStepUpAction)`), DesignSystem `StepUpFields(…, needsPassword:errorIdentifier: "account.stepUp.fieldError")` after `GET /security/2fa`; one `POST /account/deactivate` or `DELETE /account` per tap, never retried, password and code cleared as the request leaves; VoiceOver focus on its title on appear (`titleFocus:`); a 401 inline, with keyboard focus back to Password (`fieldFocus:`), a delete 409 closes the sheet and Delete account re-checks; the field error and the banners in the content are scrolled into view above the bar (`PinnedActionBar(keyboardMargin: true)`); success calls `services.session.endSessionAfterAccountClosed(_:)` (no logout request) and the root cross-fades to Welcome, which shows the toast.
   - **Delete account** (B5.16, B5.17) `DeleteAccountView.swift`: the explanation, then three parallel uncached reads (`GET /dashboard/summary`, `GET /circles`, `GET /goals`) on appear, on reappear and on pull to refresh; Domain's `DeleteAccountPrecheck` gives the rows (balance, forming or active groups, goals; words and VoiceOver values from Domain), the ErrorState "We couldn't check your account", or the clear state; after a 409, a banner says what the re-check found (none when it fails: the ErrorState alone); the destructive "Delete account" with its reserved reason line opens the B5.17 dialog, then the step-up sheet. Groups and Goals rows switch tabs (`navigator.select`).
2. **Profile** (B5.3) `ProfileView.swift`: `API.Profile.get()` / `API.Profile.update(ProfileUpdate(...))`, live username check via `services.session.isUsernameAvailable`, Email and Date of birth as DesignSystem `ReadOnlyField`s ("Verified" pill from `services.session.currentUser?.emailVerified`), "Save changes" in `PinnedActionBar(hardEdge: true)` with its reserved `DisabledReasonLine`.
3. **Security** (B5.4) and **Change password** (B5.5) `SecurityView.swift`: `API.Security.twoFactorStatus()` as a `SettingsValueRow` ("Off"/"On" words), the app lock `SettingsToggleRow` (`services.appLock`), two `SettingsGroupFootnote`s. Change password starts from the status Security loaded (`AccountFlowState.twoFactorStatus`); a 401 shows inline and never signs out.
4. **Notifications** (B5.6) `NotificationSettingsView.swift`: `SettingsSelectableRow` levels (ink checkmark, "Recommended" word) and `SettingsToggleRow` categories for Custom; optimistic save with revert. UI "Groups" = API `social`, "Tips" = `engagement`.
5. **Technical details** (B5.7 amended, B5.13) `TechnicalDetailsView.swift`: the device setting `services.settings.showTechnicalDetails`; when on, `API.Wallet.info()` network and address in DesignSystem `TechnicalDetailsRow`s, and the send-only warning (amber `NoticeBanner`, `account.technical.sendWarning`) under the USDC footnote exactly when the address shows with Copy (Domain's `SendWarningRule`; the sentences stay in this file, on the copy check's allow-list).
6. **About and legal** (B5.8, B5.8 amended) and **Disclosure detail** (B5.9) `AboutView.swift`: version (`services.buildInfo.displayVersion`) as a `SettingsValueRow`, the disclosures from DesignSystem's `Disclosure`: "About your balance" always, "Test money" in Debug builds only (`#if DEBUG`, compiled with Add test money). No font licences.
7. `AccountComponents.swift`: `AccountRoute` (with `.deleteAccount`), `AccountStepUpAction`, `AccountSheet`, `AccountFlowState`, `AccountLayout` (content tops), `AccountInitials`, `AccountEmail` (a display-only break point after "@" so a long email wraps there at accessibility sizes). Skeleton lines are DesignSystem's `SkeletonTextLine`. Every row, field, banner and bar is DesignSystem's; there are no local copies.

## Rules that bite
- "USDC" and the other crypto words may appear only in `AboutView.swift` and `TechnicalDetailsView.swift` (CopyCheckTests allow-list); the UI tests also ban "address" on Account, Profile, Security, Change password and Notifications.
- Never store the current password; clear it and the code after each request.
- Pushed screens carry no toolbar items: the first bar button must stay the system Back (the tests go back with it).
- Deactivate and delete only on throwaway accounts in tests (`AuthTestAPI.registerVerifiedAccount(enableTwoFactor:)`); the demo account is read only. A sheet chosen in a dialog is presented once the dialog has gone (B5.14 note), never in its button's action.
- The Delete account reads are never served from `SnapshotCache`; a failed read is an error, never "nothing in the way". iOS never shows the server's 409 sentences.
