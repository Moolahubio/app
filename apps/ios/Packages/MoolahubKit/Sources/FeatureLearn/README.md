# FeatureLearn: Learn list and lesson reader

**Owner:** lane L (feature wave 1) · **Spec:** the wave-1 feature spec (private) §3 and its Learn part L.3 to L.10 · `apps/ios/DESIGN.md` v2.2 (private)

## Keep (AppFeature calls these)
- `public struct LearnListView: View`, `init(services:)`: pushed for `AppDestination.learn` from Home's "See all" and Account's `account.row.learn` (inline title "Learn", root `learn.scroll`).
- `public struct LessonView: View`, `init(services:slug:)`: pushed for `AppDestination.lesson(slug:)` from Home's lesson row, the list and the reader's own next row (root `lesson.scroll`, no bar title at rest).

## What is built
- **Learn list** (L.3, SPEC §3.2), `LearnListView.swift`: `GET /learn/lessons` through `RemoteResource` (`SnapshotKey.lessons`, shared with Home), loaded on the first appearance, re-read on every later one (back from a lesson) and on pull to refresh. Intro (`learn.intro`); progress line "{done} of {total} lessons done" (`headline`, tabular) over a 6 pt `ProgressBar`, one element `learn.progress`; the featured tile (`learn.featured`): label "Start here" / "Next lesson", title `bodyEmphasis` (D-15), summary, "{n} min · {Level}", on a `surface` tile with `PressableCardButtonStyle`; "All lessons" (`learn.allHeading`); one `SettingsRow` per visible lesson (`learn.lesson.<slug>`, no symbol, `titleLineLimit: 1` (D-40), sub-line "{Category} · {n} min", value "Done"). The rows list every visible lesson, the featured one included.
- **Lesson reader** (L.4, SPEC §3.3), `LessonView.swift`: `GET /learn/lessons/{slug}` through `RemoteResource` (`SnapshotKey.lesson(_:)`), plus the list's snapshot for the header prefill and the next row. Title `titleLarge` 12 pt below the bar (`lesson.title`; VoiceOver focus on the first arrival only, so Back from the next lesson leaves focus where iOS restores it), meta, summary, then the article in the reading rhythm (headings 24 above, 8 below; `lesson.section.<i>.heading` / `.text`), "Key takeaways" (52 above, 16 to the first, 12 apart; `lesson.takeaway.<i>`), Mark as done or Done 24 below (one 50 pt frame), the next row 24 below (`lesson.next`).
- **Title in the bar** (SPEC §3.3): a `GeometryReader` background on the content title sends its maxY in the scroll view's named coordinate space (`LessonScrollSpace`) through `LessonTitleMaxYKey`; at or above 0 the bar shows `.navigationTitle(lesson.title)`, else "".
- **Mark as done** (L.6): `POST /learn/lessons/{slug}/complete`. Not optimistic: "Saving…" in the button (taps ignored), "Done" only after the 200, with VoiceOver focus moved to it and the announcement "Marked as done." (high priority, so the focus move does not cut it off); the person stays on the lesson; the lesson and the list are re-read in the background to update both snapshots (failures there show nothing). A failure keeps "Mark as done", shows `lesson.markDone.error` 12 pt above it with L.6's words (404 "We couldn't find that lesson.", 400/403/5xx/invalid "Something went wrong. Please try again.", the rest `APIError.message(for: .action)`, so no response, offline and a gateway's 502 to 504 read "We couldn't reach MoolaHub…"; nothing for an expired session), plays `.error` once and scrolls the least that shows the button whole again (the banner above it pushes it down, maybe under the tab bar).
- **Next lesson** (L.7): `LearnCatalog.next(after:in:)` over the visible list, pushed on the same stack; none after the last visible lesson, none while the list is loading or failed.
- **States.** List: skeleton at the final layout (`learn.loading`, "Loading lessons…"); `ErrorState` "We couldn't load lessons" (`learn.error`, no count); `EmptyState` "No lessons yet" (`learn.empty`); with data, the status block (`learn.banner`, `learn.updated`). Reader: prefilled header with a body skeleton, or a full skeleton (`lesson.loading`, "Loading lesson…"); `ErrorState` "We couldn't load this lesson" (`lesson.error`; "Try again" re-reads the lesson, and the list too when it never loaded, since the next row needs it); not found, title only, no button (`lesson.notFound`) for 404, 400 and any lesson outside the shown categories; the status block (`lesson.banner`, `lesson.updated`).
- `LearnSupport.swift`: the screens' words (`LearnCopy`, SPEC §6.3), the reader's own error words (`LessonErrors`) and the title-in-the-bar measurement.

## Rules that bite
- What is shown and counted is `LearnCatalog` (Domain, shared with Home): visible categories only, server order, progress from the visible list, never the dashboard's lesson counts. Crypto and remittance lessons never show, whatever path opens them (the reader's visibility guard).
- No lesson emoji anywhere (`emoji` is decoded and never drawn). Lesson text is plain text: `Text(verbatim:)`, never Markdown.
- Every word on these screens is a SPEC §6.3 row (W10.9-ln); the server's "Lesson not found" is never shown.
- UI tests: `MoolahubUITests/LearnFlowUITests.swift` (L.10 tests 1 to 3 and 5 to 7, and the bar title test). Test 1 walks the list's words and test 3 every visible lesson's words (AC9); the bar title test scrolls in 20 pt steps, so it checks the bar stays empty while the title is only partly under it. They enter through Account's `account.row.learn` (lane A); Mark as done runs on a throwaway account, so the demo account is only read. `testLearnInDarkMode` needs the simulator in dark appearance (`xcrun simctl ui '<sim>' appearance dark`, then that test alone) and skips in light.
